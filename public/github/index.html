GitHub with Visual Studio 2022 · beginner guide

Push and pull your first file with Git and GitHub

This guide shows you how to use Git inside Visual Studio 2022, one step at a time. You’ll set up Git, copy a GitHub repository to your computer, work on a branch, then push a simple text file up to GitHub and pull a teammate’s changes back down.

  • Sign in to GitHub from Visual Studio
  • Set your Git name, email and global settings
  • Create a repository on GitHub and clone it
  • Create, switch and tidy up branches
  • Commit and push a file, then fetch and pull changes
  • Fix a merge conflict and merge a pull request

How Git moves your work around

Git keeps a full history of your files. Most of the time you work on your computer. You only talk to GitHub when you push (send) or fetch/pull (receive).

How to use this guide

  • Pick sections from Solution Explorer on the right, or press the green ▶ Next section button in the toolbar.
  • The screen pictures are step-by-step tours with two modes:
    • Show me walks you through each step. Click a numbered dot, use the ‹ › buttons, or press the arrow keys. The instructions appear under the picture.
    • Try it gives you a task, such as “Choose Account Settings…”, and you click the right place yourself. The menus are full of real-looking options, so you practise finding the right one. Get it wrong twice and the answer is outlined for you.
  • The menu bar at the top of this page works too. Open File, Git or Tools and try finding things. Items with a blue section number take you to that part of the guide. The others are dummy items, there to make it feel like the real thing.
  • Grey boxes marked OPTIONAL show the same thing as a typed Git command. You don’t need them, but they help when you read help pages online.
  • Tick Mark section as done at the bottom of each section to track your progress.
Using Visual Studio 2026? The Git tools work the same way and live in the same menus. Some icons and colours look a little different.
1.1 Git and GitHub in plain words ›

1.1 · Getting started

Git and GitHub in plain words

Git is a program on your computer that remembers every saved version of your files. GitHub is a website that stores a copy online, so you can share it and work as a team.

WordWhat it means
Repository (repo)A project folder that Git is tracking, with its full history.
CloneDownload a repository from GitHub to your computer for the first time.
CommitA saved snapshot of your changes, with a message saying what changed. Commits stay on your computer until you push.
StageChoose which changed files go into the next commit. Optional in Visual Studio.
PushSend your new commits up to GitHub.
FetchCheck GitHub for new commits, without changing your files.
PullFetch, then merge those commits into your files.
BranchA separate line of work. You can try things on a branch without touching main.
mainThe default branch. Usually the “finished, working” version.
originGit’s nickname for the GitHub copy you cloned from.
MergeCombine the commits from one branch into another.
Merge conflictTwo people changed the same lines, so Git asks you to choose.
Pull request (PR)A GitHub page asking for one branch to be merged into another, so others can review it first.

Branches in one picture

In this guide you’ll make the add-hello branch, add commits to it, then merge it back into main with a pull request.

1.2 · Getting started

Check Visual Studio has Git

Visual Studio 2022 installs Git for Windows for you with almost every workload. You only need to check it’s there.

Quick check

  1. Open Visual Studio 2022.
  2. Look at the menu bar. If there is a Git menu between View and Project, you are ready. Skip to section 1.3.

If there is no Git menu

  1. Close Visual Studio. Open Visual Studio Installer from the Start menu.
  2. Next to Visual Studio 2022, press Modify.
  3. Open the Individual components tab and search for git.
  4. Tick Git for Windows, then press Modify at the bottom right.
  5. When it finishes, open Visual Studio again.
Already have Git installed separately? That’s fine. Visual Studio uses its own copy, and both read the same settings file, so your name and email are shared.

You also need

  • A free GitHub account. Sign up at github.com/signup if you haven’t got one.
  • Two-factor authentication turned on in GitHub (GitHub asks for it). The authenticator app on your phone is easiest.

What the other settings do

SettingUseWhy
Prune remote branches during fetchTrueBranches deleted on GitHub vanish from your list too, so it doesn’t fill up with old ones.
Rebase local branch when pullingFalsePull merges. Rebase rewrites history, which is useful later but confusing at first.

Global or repository settings?

Underneath, there is also Git Repository Settings. Anything set there applies to the open repository only, and wins over the global value. For example, you could use a work email in one repository only.

The everyday loop

  1. On main, Pull.
  2. Create a branch for your change.
  3. Edit, save, Commit. Repeat as often as you like.

  5. Merge it, switch to main, Pull, delete the branch.

8.2 · Reference

Troubleshooting

First, check the Output window (View › Output, then choose Source Control - Git). It shows the real Git message.

Message or problemWhat it meansFix
Please tell me who you are / user.email not setGit doesn’t know your name and email.Do section 2.1, then commit again.
Authentication failed or 403 on pushGit Credential Manager has an old or wrong sign-in, or you don’t have write access to the repository.File › Account Settings: remove and re-add GitHub. In Windows, open Credential Manager › Windows Credentials and remove entries for git:https://github.com. Check you own the repository or have been added as a collaborator.
Updates were rejected because the remote contains work that you do not haveSomeone pushed first.Pull, fix any conflict, then Push again. Don’t force-push.
Your local changes would be overwritten by checkout/mergeYou have uncommitted changes that clash.Commit them, or Stash All (Commit All ▾), then try again.
Branch from GitHub isn’t in the listYour computer hasn’t fetched since it was made.Press Fetch.
Detached HEADYou checked out a single commit rather than a branch.Switch back to a branch with the status-bar branch picker. If you made commits, create a new branch first so you keep them.
Files you never changed show as modifiedUsually line endings (Windows CRLF vs LF).Leave Git’s default (core.autocrlf true on Windows). Undo those changes in Git Changes.
bin, obj or .vs appear in Git ChangesThere’s no .gitignore, or it was added after the files were committed.Add the VisualStudio .gitignore. For already-committed files run git rm -r --cached bin obj, then commit.
Clone says the folder is not emptySomething already exists at that path.Choose a new folder name in the Path box.
Git menu missingGit for Windows component not installed.See section 1.2.

Get unstuck safely

  • Abort a merge you don’t understand yet. It puts everything back.
  • Until you push, everything is only on your computer. Mistakes in local commits are easy to fix.
  • Copy your changed files somewhere safe before trying anything drastic.
  • Never delete the .git folder to “start again”: that deletes the history. Clone a fresh copy into a new folder instead.
