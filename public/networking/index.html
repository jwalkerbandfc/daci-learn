A networking course where you build the network. Drag real equipment onto a diagram, wire it up, set it up, send a packet and watch where it goes. Every task is marked, and every mark comes with a reason.

  • 15 marked tasks and 10 marked exercises: over 230 marks, with feedback on every line

1.2 · Getting started

Your first network

Two computers and one cable. It is the smallest network you can make, and almost everything later is this with more boxes.

Everything you need is in the workbench below. The task panel on the right says what to do and what is marked.

What just happened

When you pressed ping, the first PC did three things:

  1. Compared the addresses. 192.168.10.1 and 192.168.10.2 with the mask 255.255.255.0 are on the same network, so the other PC is a local neighbour. No router needed.
  2. Asked who that is. It sent an ARP request to everyone: who has 192.168.10.2? The other PC answered with its MAC address.
  3. Sent the ping. Four echo requests, four echo replies.

Open the Trace tab and step through it. Every line is one hop, and the box at the bottom shows what was inside the message at that moment.

How it works: why a crossover cable

An old Ethernet port sends on one pair of wires and listens on another. Two PCs both send on the same pair, so joined with a straight cable they would shout at each other and listen to silence. A crossover swaps the pairs so that send meets listen.

Modern equipment has auto-MDIX, which spots the problem and swaps the pairs itself, so in real life a straight cable usually works anywhere. This guide keeps the old rule switched on because exams still ask for it, and because it makes the reason visible.

Your turn: Change one PC's address to 192.168.11.2 and ping again. Why does it fail now, even though the cable is fine?
Show the answer

With the mask 255.255.255.0, 192.168.10.1 and 192.168.11.2 are on different networks. The first PC decides the other one is not a local neighbour, looks for a default gateway to hand the packet to, finds none, and gives up. The cable is irrelevant: this is a layer 3 problem, not a layer 1 one.

2.1 · How networks work

What a network is for

A network is two or more devices that can send each other data. Everything else is detail, but the detail is where the job is.

What a network gives you

Sharing filesOne copy of a document, in one place, that the right people can open and change.
Sharing hardwareOne printer for thirty people, instead of thirty printers.
CommunicationEmail, chat, voice and video between people who are not in the same room.
Central controlOne place to set up accounts, apply updates and take backups.
Access to servicesWebsites, cloud storage and apps that live somewhere else entirely.

The four things every network needs

  1. Devices that want to talk: computers, phones, printers, servers, cameras, sensors.
  2. A medium to carry the signal: copper, glass fibre or radio.
  3. Equipment in the middle to join them up and make choices: switches, routers, access points.
  4. Rules that everyone follows, so that a laptop made in Taiwan can talk to a server in Dublin. These rules are called protocols.

Why rules matter more than wires

Two devices can be connected by a perfect cable and still fail to communicate, because communication needs agreement about:

  • How a 1 and a 0 are sent as voltage, light or radio.
  • Where one message stops and the next one starts.
  • Who the message is for, and who it is from.
  • What to do if it arrives broken, or does not arrive at all.
  • What the message means once it has arrived.

Each of those is a different job, and each is handled by a different layer. That is the idea behind the OSI model in section 2.4.

Three words people mix up A protocol is a set of rules (HTTP, IP, Ethernet). A standard is a published, agreed protocol (IEEE 802.3 is Ethernet). A service is something useful built on top of them (a web server, a file share).
Your turn: Name three things that stop working in a school if the network goes down, and one thing that still works.
Show the answer

Stops: shared drives, printing, the register system, email, the internet, cloud documents, the phone system if it is VoIP. Still works: anything already open and saved locally, and anything on paper. The point is how much of an organisation now depends on one set of wires.

2.2 · How networks work

Clients, servers and peers

Who asks, and who answers? That one question decides how a network is designed, paid for and secured.

Client and server

A client asks for something. A server answers. A web browser is a client; the machine holding the page is a server. One computer can be both at once.

In a client-server network the important things live on servers that are always on, looked after and backed up. Almost every organisation works this way.

GoodNot so good
Files, accounts and backups are in one placeServers cost money and need looking after
One change applies to everyoneIf the server is down, everybody is stuck
Easier to secure and to auditNeeds someone who knows what they are doing

Peer to peer

In a peer-to-peer network every device is equal: each one shares some of its own files and uses other people's. Home networks and small offices often work this way, as do file-sharing systems and some blockchain networks.

GoodNot so good
Cheap: no server to buyFiles are scattered across machines
Simple to set upNo central backup or accounts
No single point of failureFalls apart beyond about ten devices

Where the work happens

  • Thin client: the device is a screen and keyboard; the work happens on a server. Easy to manage, useless without the network.
  • Thick (fat) client: the device does the work itself and uses the network to fetch and save. Keeps working offline.
  • Cloud: somebody else's servers, rented by the hour. The pattern is still client-server; the server is just not yours.
In the workbench The Server device is a client-server setup in one box: it can hand out addresses, answer names and serve a page. The PCs are clients. You will build exactly that in section 7.5.
Your turn: A school has 400 pupils who all log in and find their own documents on any machine in the building. Client-server or peer to peer, and why?
Show the answer

Client-server. The accounts and the documents have to live somewhere central, or logging in on a different machine could not possibly show you your own files. Peer to peer would mean your work only existed on the one computer you happened to use.

2.3 · How networks work

LAN, WAN and the internet

The same ideas work at the size of a room, a building, a city or the planet. The names change with the distance.

NameSizeWho owns itExample
PAN personal area networkA few metresYouBluetooth earbuds, a smart watch
LAN local area networkOne building or siteThe organisationA school, an office, your home
WLAN wireless LANOne buildingThe organisationThe Wi-Fi inside that school
MAN metropolitan area networkA town or cityA council or providerA council joining its libraries together
WAN wide area networkAnywhereLeased from a providerTwo offices in different cities, joined
The internetGlobalNobody, and everybodyA network of networks that agreed on IP

The important line is LAN or WAN

Inside a LAN you own the cable. You decide the speed, the addresses and the rules, and it costs nothing per gigabyte. LAN links are fast (1 Gbps upwards) and have very low delay.

A WAN link crosses ground you do not own, so you rent it from a provider. It is slower, further, and has a bill attached. That is why networks are built so that most traffic stays local, and only what has to cross the WAN does.

This is also why the equipment differs: a switch does the local work, and a router stands at the boundary and decides what is worth sending out.

Topologies: how they are joined up

MeshMany devices join to many othersThe internet core, wireless mesh
BusOne shared cable with everything tapped onto itOld Ethernet, obsolete
RingEach device joins the next, in a circleOld token ring, some fibre backbones

The star is everywhere because one broken cable takes out one device, and because adding a device means plugging it in. Its weakness is the switch: if that dies, everything on it stops, which is why section 9.4 adds a second one.

Which one is this guide? Every task you build is a star LAN. Section 6.4 adds a WAN link between two sites, and section 7.5 adds the internet.
Your turn: Your two offices are 40 miles apart and need to share one file server. Which link do you need, and name one thing you must plan for that a LAN never makes you think about.
Show the answer

A WAN link between the two sites, rented from a provider. You have to plan for the delay and the limited bandwidth: opening a large file over a WAN is much slower than over a LAN, so the design often keeps a copy at each site, or uses a system built for slow links.

2.4 · How networks work

The OSI model

Seven layers, each doing one job and handing the result to the next. It is a map for thinking, and it is what every fault-finding method is built on.

The seven layers

#LayerIts one jobYou will meet
7ApplicationThe thing the user wantsHTTP, DNS, SMTP
6PresentationFormat, encrypt, compressTLS, JPEG, UTF-8
5SessionStart, manage and end a conversationLogins, sockets
4TransportEnd to end delivery, in order, to the right programTCP, UDP, port numbers
3NetworkAddressing and choosing a path between networksIP, routers
2Data linkGetting a frame across one link, to the right cardEthernet, MAC, switches
1PhysicalOnes and zeros as voltage, light or radioCables, connectors, radio

Why anyone cares

Three real reasons:

  1. Fault finding. Start at layer 1 and work up. Is it plugged in? Is the link light on? Does it have an address? Can it reach the gateway? Does the name resolve? Is the service running? You will use this exact ladder in Part 10.
  2. Swapping parts. Because each layer only talks to the ones either side, you can change the cable (layer 1) from copper to fibre without changing a single thing about IP (layer 3).
  3. Talking to other people. "It is a layer 2 problem" tells a colleague more in four words than a paragraph would.
5, 6 and 7 in real life In practice the top three are usually treated as one. A browser speaking HTTPS is doing application, presentation (TLS encryption) and session work at the same time. The TCP/IP model in the next section admits this and uses four layers.
Common mistakes
  • Mixing up the switch and the router. A switch works at layer 2 with MAC addresses, inside one network. A router works at layer 3 with IP addresses, between networks.
  • Thinking data physically travels up and down inside the cable. The layers are a way of dividing up the job. What travels is one stream of bits, with each layer’s header wrapped around the one above it.
Your turn: A user says "the website is down". The link light is on, ipconfig shows a good address, pinging the gateway works, but nslookup fails. Which layer is the problem, and what is the likely cause?
Show the answer

It is a layer 7 problem: DNS. Layers 1 to 3 have been proved to work by the link light, the address and the successful ping. The likely cause is a wrong or unreachable DNS server address, which you can see in ipconfig /all.

Your turn: A frame arrives at a switch. Which headers does the switch read, and which does it ignore?
Show the answer

It reads the layer 2 Ethernet header: the destination MAC to decide where to send it, and the source MAC to learn from. It ignores the IP header and everything above, which is why a switch cannot route between networks and why it is so fast.

Protocols you will meet

A handful of protocols does almost everything. Learn what each one is for, and most of networking stops being mysterious.

The ones worth knowing

ProtocolPortWhat it does
HTTP / HTTPS80 / 443Web pages. HTTPS is HTTP inside TLS encryption.
DNS53Names to addresses.
DHCP67, 68Hands out addresses and settings.
SMTP25, 587Sending email.

FTP / SFTP21 / 22Moving files.

ICMPnoneTest and error messages. ping and tracert use it.

TCP or UDP

Both are layer 4, and both use port numbers to say which program the data is for. The difference is how much care they take.

TCPUDP
Sets up firstYes, a three-way handshakeNo, just sends
Lost dataNoticed and sent againGone

A video call would rather drop a frame than pause for half a second to fetch it again. A bank transfer would rather wait.

Port numbers

An IP address gets a packet to the right computer. A port number gets it to the right program on that computer. A web server listens on port 80; your browser picks a random high port for itself, so replies know where to come back to. That pair of addresses and ports is a socket, and it is what makes it possible to have twenty tabs open at once.

Where you will see ports In the workbench, open the Trace tab after fetching a web page. The layer 4 line shows 49152 → 80: a random port on the PC, port 80 on the server.
Your turn: You can ping a web server by IP address, but the website does not load. Name two different causes, one at layer 7 and one at layer 4.
Show the answer

Layer 7: the web server software is not running, so nothing is listening. Layer 4: a firewall is blocking TCP port 80 or 443 while still allowing ICMP, which is why the ping works. Both look identical to the user.

3.1 · Cables and signals

Copper cables

Almost every desk in the world is joined to its switch by four twisted pairs of copper inside one plastic sheath.

Why the pairs are twisted

Electricity in a wire makes a magnetic field, and a magnetic field induces current in nearby wires. That unwanted leak is crosstalk, and it is what turns data into rubbish.

Twisting two wires together fixes it twice over. The two wires of a pair carry the same signal in opposite directions, so the interference they pick up is equal and cancels out when the receiver subtracts one from the other. And because each pair has a different twist rate, neighbouring pairs do not stay side by side long enough to interfere with each other.

The categories

CableSpeed it is rated forWhere you find it
Cat 5e1 Gbps up to 100 mStill the most common in older buildings
Cat 61 Gbps, or 10 Gbps up to 55 mThe normal choice for new work
Cat 6a10 Gbps up to 100 mData centres, backbones, new builds
Cat 7, Cat 825 to 40 Gbps, short runsData centre racks

UTP (unshielded twisted pair) is standard. STP (shielded) wraps foil around the pairs for places with heavy electrical noise, such as a workshop with motors, but it costs more and must be earthed properly to work at all.

The 100 metre rule A copper Ethernet run must not be longer than 100 m, including the patch leads at both ends. Past that the signal is too weak and too distorted to be read reliably. If you need to go further, you need fibre, or a switch in the middle.

Wiring the plug

Eight wires go into an RJ45 plug in a fixed order. There are two standards, T568A and T568B, and they differ only by swapping the orange and green pairs. Most of the UK uses T568B. It does not matter which you pick, as long as both ends of the same cable match.

The four pins that matter At 100 Mbps only pins 1, 2, 3 and 6 carry data: the orange pair sends and the green pair receives. That is why the orange and green pairs are split across the plug rather than kept together, and why a cable with the blue and brown pairs broken still works at 100 Mbps and fails at 1 Gbps, which uses all four pairs.
Common mistakes
  • Untwisting too much at the end. Keep the twists right up to the plug. More than about 13 mm untwisted and a gigabit link starts dropping packets.
  • Using a different standard at each end. T568A at one end and T568B at the other makes a crossover cable, by accident.
Your turn: A 1 Gbps link between two switches keeps falling back to 100 Mbps. The cable is Cat 6 and 30 m long. What is the most likely fault?
Show the answer

A broken or badly terminated wire in the blue or brown pair. Those two pairs are only used at 1 Gbps, so the link still works at 100 Mbps and the fault is invisible until you look at the speed. Re-terminate both plugs, or test the cable.

Fibre optic

A glass core thinner than a hair carries pulses of light. There is no electricity in the cable at all, which means:

MAC addresses

Every network card is born with an address burned into it. Switches use it, and it never changes.

What a MAC address looks like

00:1B:44:11:3A:B7 — six pairs of hexadecimal digits, 48 bits in total.

  • The first three pairs are the OUI: the code for the company that made the card. 00:1B:44 is one of Cisco's.
  • The last three pairs are that company's serial number for the card.

Between them they are supposed to be unique in the world. It is a physical or hardware address, and it works at layer 2, inside one network only. A MAC address never crosses a router.

Two special ones matter:

  • FF:FF:FF:FF:FF:FF is the broadcast address. Everything on the network accepts it.
  • The first bit of the first byte marks a multicast address, meant for a group.

Masks and networks

The mask is the thing that tells a device which part of an address is the network. Get it wrong and nothing works, even though every address looks fine.

How a mask works

A mask is 32 bits, written like an address. Every 1 means this bit is the network part; every 0 means this bit is the host part. The ones always come first.

The device does a bitwise AND of the address and the mask. What comes out is the network address.

Counting the ones gives the shorter prefix notation: 255.255.255.0 has 24 ones, so it is written /24, and the whole thing becomes 192.168.1.104/24.

Usable is always 2 to the power of the host bits, minus two: one for the network address, one for the broadcast.

The decision every device makes

Before sending anything, a device compares its own network address with the destination's:

  • Same network? Send it straight to the device. ARP for its MAC, then out of the cable.
  • Different network? Send it to the default gateway and let the router deal with it.

That one comparison explains most "it cannot see the server" faults. If two machines that should be neighbours have different masks, each can reach the other sometimes and not others, which is maddening until you check.

/30 and point-to-point links

A link between two routers only ever needs two addresses, so a /30 is used: four addresses, two usable, one network, one broadcast. You will use 10.10.10.0/30 in section 6.4. Nothing is wasted.

Common mistakes
  • Mask typed as 255.255.0.255. A mask has to be all ones then all zeros. The workbench and real equipment will both refuse it.
  • Two machines, same network, different masks. One thinks the other is local and the other does not. Traffic goes one way and not the other.

Subnetting

Subnetting is splitting one network into several smaller ones. It is the skill every networking exam tests, and it is just counting in binary.

Why split a network up

  • Less broadcast traffic. A broadcast goes to everything in its network. 500 machines in one network means every ARP reaches all 500.
  • Security and separation. Finance on one subnet, guests on another, with a router (and rules) in between.
  • Tidy addressing. One subnet per floor, per department or per site makes faults easier to place.
  • Fewer wasted addresses. A link between two routers needs two addresses, not 254.

The method that always works

To split a network, borrow bits from the host part and give them to the network part.

Take 192.168.1.0/24 and split it into four:

  1. How many subnets? 4. Two bits gives you 4 ( 2² ), so borrow 2 bits.
  2. New prefix: 24 + 2 = /26, which is 255.255.255.192.
  3. Block size: 256 − 192 = 64. The subnets start every 64 addresses.
  4. Write them out:

NAT: how private addresses reach the internet

Network Address Translation sits in the router. When a packet goes out:

  1. The router swaps the private source address for its own public address.
  2. It writes down which internal device and port the request came from.
  3. When the reply arrives, it looks up the note and sends it to the right machine inside.

One public address can serve hundreds of private ones, because the port number keeps each conversation apart. That version is usually called PAT, port address translation, or NAT overload.

5.1 · Switching

What a switch does

A switch starts knowing nothing. Within one frame it has started learning, and that learning is the whole trick.

The three rules a switch follows

  1. Learn. Every frame that arrives has a source MAC address. The switch writes down that address is on this port.
  2. Forward. If the destination address is in its table, send the frame out of that one port.
  3. Flood. If the destination is not in the table, or is the broadcast address, send it out of every other port.

That is it. No addresses to configure, no setup: plug it in and it works. It is also why switches are fast: the decision is a table lookup done in hardware.

What you should have seen

  • The first ping floods, because the table is empty.
  • The table then has two entries, one for each PC that has sent something.
  • The second ping does not flood: the trace says SW1 knows that address, so it sends the frame out of Fa0/1 only.
  • PC2, which is plugged in but was not part of the conversation, still appears in nothing. A switch only learns from frames it actually receives.
Ageing A real switch forgets an entry after about five minutes of silence, so that a laptop moved to another port is found again. In this simulator entries stay until you press Empty the table.
How it works: full duplex, and why switches killed hubs

Each switch port is a separate conversation, so a device can send and receive at the same time: full duplex. There is nothing to collide with, because there is nobody else on that piece of cable.

A hub cannot do this. Everything on a hub shares one conversation, so devices must take turns and detect collisions, which is half duplex. A 100 Mbps hub shared by ten machines gives each of them a slice of 100 Mbps. A 100 Mbps switch gives each of them 100 Mbps in each direction at once.

Your turn: A switch has 24 ports and a full MAC table. You unplug a laptop from port 5 and plug it into port 12, then ping from it. What happens?
Show the answer

The first frame from the laptop arrives on port 12, so the switch immediately updates its table to say that MAC address is now on port 12. Traffic going the other way, sent before the laptop spoke, would have been sent to port 5 and lost. This is why entries also age out.

5.2 · Switching

Hubs, switches and collisions

Before switches there were hubs, and they explain by contrast why a switch is such a good idea.

What a hub does

A hub is a repeater with several sockets. A signal arriving on one port is copied, electrically, to every other port. It has no table, no addresses and no idea what it is carrying.

Two consequences follow:

  • Everything is shared. All the bandwidth, all the time, between everyone.
  • Everything is visible. Every machine receives every frame and is trusted to ignore the ones not addressed to it. Anyone can read the lot.

Collisions

If two devices on a hub send at the same moment, the signals overlap and both are ruined. That is a collision. Ethernet handles it with CSMA/CD:

  1. Carrier sense: listen before sending.
  2. Multiple access: everyone shares the one wire.
  3. Collision detection: if you hear a clash while sending, stop, send a jam signal, wait a random time, and try again.

It works, but as the number of machines grows the number of collisions grows faster, and a busy hub can spend more time colliding than sending.

  • Exams still ask.
  • The ideas (collisions, half duplex, shared medium) come straight back in wireless, where everybody really does share the air.
  • Plugging a hub in is still the simplest way to watch someone else's traffic, which is a security point worth knowing.
Try it in the workbench Build two PCs on a hub and ping. Look at the trace: the hub repeats the frame out of every port, every time, no matter how many times you ping. It never learns.
Your turn: Twelve machines share a 100 Mbps hub. Roughly what throughput does each one get, and what happens if you swap the hub for a switch?
Show the answer

On the hub they share 100 Mbps between them, so under 10 Mbps each in practice, and worse as collisions rise. With a switch each port gets its own 100 Mbps in each direction and there are no collisions at all, so the machines only compete when several of them talk to the same destination at once.

5.3 · Switching

VLANs

One switch, several separate networks. A VLAN is the switch pretending to be two switches, and it is everywhere in real buildings.

The idea

Without VLANs, every port on a switch is in one big network, and a broadcast from any device reaches all of them.

A VLAN (virtual LAN) tags each port with a number. The switch then refuses to move frames between ports with different numbers. Ports 1 to 8 might be VLAN 10 and ports 9 to 16 VLAN 20, and the two groups cannot see each other at all, even though they are in the same box on the same shelf.

Why it is worth doing

  • Separation without buying switches. Staff, guests, phones and cameras can share the hardware without sharing the network.
  • Smaller broadcast domains. A broadcast only reaches its own VLAN.
  • Security. A visitor who plugs into a guest port cannot see the finance machines, whatever they try.
  • Flexibility. Moving someone to another department is a setting, not a cable.

Access ports

A port that belongs to exactly one VLAN is an access port. That is what a PC, a printer or an access point plugs into. The device has no idea the VLAN exists: frames arrive and leave with nothing added.

Notice what did not fix it

In that task all four PCs are on the same IP network, 10.0.0.0/24, and staff still cannot ping guests. Changing an IP address would not help either. The block is at layer 2: the switch simply will not carry the frame between the two groups of ports.

To let them talk you need something that works at layer 3, which is section 6.5.

VLAN 1 Every switch port starts in VLAN 1. Leaving unused ports in VLAN 1 is a habit worth breaking: anyone who plugs into a spare socket lands in the same VLAN as your management traffic. Good practice is to put every unused port into a dead VLAN and switch it off.
Your turn: A school puts pupils in VLAN 30 and staff in VLAN 10. A pupil unplugs a staff PC and plugs their laptop into that socket. What do they get?
Show the answer

Whatever that port is configured for, which is VLAN 10: the staff network. VLANs follow the port, not the device. That is why serious networks add 802.1X, which makes the device prove who it is before the port is turned on, or at least switch off unused ports.

5.4 · Switching

Trunks and tagging

Access ports carry one VLAN. A trunk carries all of them down a single cable, by writing a tag on every frame.

The problem a trunk solves

Two switches, each with VLAN 10 and VLAN 20 on them. You want VLAN 10 on one switch to reach VLAN 10 on the other, and the same for 20, but you only want to run one cable.

An access port cannot do it: it only carries one VLAN, and it strips any information about which. So a frame arriving at the far switch would have nothing to say which VLAN it belonged to.

Tagging

A trunk port adds a small tag to every frame as it leaves, carrying the VLAN number. The switch at the other end reads the tag, puts the frame into that VLAN, and removes the tag before handing it to an access port.

The standard is IEEE 802.1Q, and the tag is four bytes added to the Ethernet header, 12 bits of which are the VLAN ID. That gives 4094 usable VLANs.

Where trunks go

LinkPort type

The native VLAN

One VLAN on each trunk is left untagged, and is called the native VLAN. It is there for old equipment that does not understand tags. Both ends must agree which VLAN that is, or traffic silently ends up in the wrong place, which is a classic and very annoying fault.

Allowed VLANs

A trunk can be told to carry only certain VLANs. In the workbench, a trunk port has an Allowed box: leave it empty for all of them, or type 10,20 to carry just those. Restricting the list is good practice: a trunk to a floor switch has no business carrying the server VLAN if there are no servers on that floor.

In the workbench Open a switch, choose Ports, and change a port's mode from Access to Trunk. You will do exactly this in section 6.5, where a single trunk carries two VLANs up to a router.
Common mistakes
  • Setting a trunk at one end and an access port at the other. One end tags and the other does not understand tags. The link looks up and nothing works properly. Always configure both ends.
  • Forgetting to allow a VLAN on the trunk. If the allowed list leaves a VLAN out, that VLAN stops at the switch. The link light is green, which makes it hard to spot.
Your turn: Two switches are joined by a trunk. SW1 has VLAN 10 on ports 1 to 4; SW2 has VLAN 10 on ports 1 to 4 as well. A PC on SW1 port 2 pings a PC on SW2 port 3. How many times is the frame tagged?
Show the answer

Once. It arrives untagged from the PC at an access port, the switch tags it with VLAN 10 as it goes out of the trunk, and SW2 removes the tag before sending it out of its own access port. The PCs never see a tag at all.

5.5 · Switching

Loops and spanning tree

Two cables between two switches is good planning. Without spanning tree it is also a way to bring the whole network down in seconds.

Why a loop is so destructive

A switch floods a broadcast out of every port. Give it two paths to another switch and the broadcast comes back, gets flooded again, comes back again, and so on. Three things then happen at once:

  1. A broadcast storm. The same frame multiplies until the links are full.
  2. MAC table instability. The switch sees the same source address arriving on different ports, over and over, and rewrites its table every time.
  3. Duplicate frames. Devices receive several copies of everything.

Unlike an IP packet, an Ethernet frame has no TTL: nothing counts the hops, so nothing ever discards it. The network does not slow down gracefully; it stops.

Spanning tree

STP (802.1D, and its faster modern version RSTP) fixes it automatically:

  1. The switches elect a root bridge, which is the one with the lowest bridge ID (a priority plus its MAC address).
  2. Each other switch works out its best path to the root.
  3. Any port that is not on a best path is put into blocking: it stays up, but it carries no data.

The result is a tree with no loops. If a working link fails, a blocked port is brought back into service within a few seconds, so you get the redundancy without the storm.

What you should have seen

  • With two cables and STP off, the ping fails and the message says there is a broadcast storm.
  • Switching STP on blocks exactly one port, shown amber in the workbench.
  • The ping then works, and the spare cable is still there, ready if the first one is cut.
In the real world Modern switches run RSTP by default, so an accidental loop usually heals itself. But people still manage it: plug both ends of one patch lead into the same switch, into ports where STP has been switched off for speed, and you can take out a floor of a building. It is one of the most common serious mistakes in networking.
Your turn: Why does a routing loop not destroy an IP network in the same way?
Show the answer

Because an IP packet has a TTL field that every router reduces by one. When it reaches zero the packet is discarded and an error is sent back. Ethernet frames have no such field, so a layer 2 loop is permanent until something outside stops it.

6.1 · Routing

What a router does

A switch moves frames inside one network. A router moves packets between networks, and decides which way they go.

What a router actually does

For every packet that arrives, a router:

  1. Checks it is for somewhere else. If the destination is one of its own addresses, it deals with it itself.
  2. Looks up the destination network in its routing table.
  3. Takes one off the TTL. If that reaches zero it throws the packet away and sends an error back. This is what stops loops.
  4. Builds a new frame. It finds the MAC address of the next hop with ARP, puts the packet in a brand new layer 2 frame, and sends it out of the right interface.

Step 4 is worth sitting with: the layer 2 frame is thrown away and rebuilt at every router, with new MAC addresses, while the layer 3 packet, with its original source and destination IP addresses, is carried the whole way unchanged.

6.2 · Routing

Default gateways

The default gateway is the address a device sends everything to when the destination is not a local neighbour. Get it wrong and the local network works perfectly while nothing else does.

The decision, again

Before sending any packet, a device compares networks:

For a local destination it ARPs for that device and sends the frame straight to it. For anything else it ARPs for the gateway, and sends the frame there, with the final destination still in the IP header.

Three rules for a gateway address

  1. It must be an address on the router, on the network the device is in.
  2. It must be inside the device's own subnet, or the device cannot reach it to hand anything over.
  3. It is normally the first usable address in the subnet (.1), purely by convention. The last (.254) is also common. Pick one and be consistent.

Symptoms of a wrong gateway

SymptomLikely cause

Some sites work, some do notDNS, not the gateway
Works from one machine, not anotherCompare ipconfig on both: it is usually the gateway or the mask
The two-ping test From a PC, ping the gateway first. If that fails, the problem is between you and the router: cable, switch port, VLAN, address or mask. If it works, ping something beyond: now the problem is the router or further out. Two pings split the problem in half.
Your turn: A PC is 10.0.5.50/24 with gateway 10.0.5.1. It can ping 10.0.5.1 but not 10.0.9.20. Where is the fault, and where is it definitely not?
Show the answer

It is definitely not the PC’s address, mask, cable, switch port or gateway setting: the successful ping to the gateway proves all of those work. The fault is beyond the router: either the router has no route to 10.0.9.0/24, or the far network cannot get back, or the destination itself is down.

Routes come in pairs

A route is one way only. If the Leeds router knows how to reach Hull but Hull does not know how to reach Leeds, the request arrives and the reply has nowhere to go. The ping fails and it looks like nothing worked at all, which is misleading: half of it worked perfectly.

This is such a common mistake that it is worth a rule: every time you add a route, ask yourself what the reply will do.

Common mistakes
  • A route pointing at the wrong end of the link. The next hop is the address at the far end, not your own. 10.10.10.1 on R1 means "send it to myself".
  • Only one router configured. Requests arrive, replies cannot get home. Always do both.
  • Interfaces left switched off. A serial link needs both ends on.

Routing between VLANs

VLANs separate; routers join. Put the two together with one cable and you get the arrangement that most small sites actually use.

The problem

After section 5.3 you have two VLANs that cannot talk to each other. That was the point, but in real life Staff still needs to reach the server in the Servers VLAN. Something must move packets between them, and that means layer 3.

Three ways to do it

Sub-interfaces

A sub-interface is a logical interface inside a physical one. Gi0/0.10 handles VLAN 10 and Gi0/0.20 handles VLAN 20, both down the same cable. Each has its own IP address, and each is the default gateway for its VLAN.

The switch port facing the router must be a trunk, so that the tags survive the journey and the router can tell which VLAN each frame came from.

Check your understanding of the path

When STAFF1 pings GUEST1, the packet goes: STAFF1 → switch (VLAN 10) → tagged up the trunk → router sub-interface for VLAN 10 → routed → back down the trunk tagged as VLAN 20 → switch → GUEST1. One cable, used twice, with the tag changing in the middle.

Open the Trace tab and look at the VLAN number on each line. You can watch it change from 10 to 20 as the router hands it back.

Why layer 3 switches won Router on a stick pushes every packet between VLANs down one cable, twice. A layer 3 switch does the routing inside the switch at full speed. The configuration looks almost identical, which is why learning it this way round is worth doing.
Your turn: After setting this up, inter-VLAN traffic works but it is slower than traffic inside one VLAN. Why?
Show the answer

Every packet between VLANs travels up the trunk to the router and back down it again, so it crosses the same cable twice and waits for the router to make a decision. Traffic inside a VLAN is switched in hardware and never leaves the switch.

Metrics

When there are two paths, the protocol picks by metric: a number for how good a route is, where lower is better. RIP counts hops, which is why it would send traffic over one slow satellite link rather than two fast fibre links. OSPF uses cost based on bandwidth, which gets that right.

Because you can see every one of them, and because nothing happens that you did not type. Once you can explain exactly what a static route does, OSPF is just a machine writing them for you.

DHCP

Nobody types an address into 300 laptops. A DHCP server hands them out, and takes them back when they are not needed.

The four steps

DHCP is a conversation of four messages, remembered as DORA:

StepWhoWhatSent to
DiscoverClientIs there a DHCP server out there?Broadcast: everyone

What a server hands out

Not just an address. A proper DHCP scope gives a client everything it needs:

  • the IP address, from a pool
  • the subnet mask
  • the default gateway
  • one or more DNS servers
  • a lease time, after which the client asks again

Getting an address but no gateway is a classic misconfiguration: local traffic works, the internet does not.

  • A reservation ties one MAC address to one address, so the printer is always 192.168.1.50.

DNS

People remember names; computers need numbers. DNS is the phone book that turns one into the other, and it is the single most common cause of "the internet is broken".

What happens when you type a name

  1. Your computer checks its own cache, and the hosts file.
  2. If it does not know, it asks the DNS server it was given (by DHCP, usually).
  3. That server checks its own cache and its own records.
  4. If it still does not know, it asks the root servers, then the .uk servers, then the servers for that domain, until it has an answer.
  5. The answer comes back and is cached at every step for a while, so the next person is quicker.

All of that happens in a few milliseconds, before a single byte of the website is fetched.

Web servers and HTTP

The service that made the internet famous. One request, one response, and a surprising amount of setting up before either.

What happens behind one click

Opening http://intranet.office.local is five separate conversations:

  1. ARP to find the router or the server's MAC address.
  2. DNS to turn the name into an address.
  3. TCP handshake: SYN, SYN-ACK, ACK.
  4. HTTP request: GET / HTTP/1.1.
  5. HTTP response: 200 OK and the page.

You saw all five in the capture in section 2.5. In the workbench, run web intranet.office.local from a PC and the trace shows the same sequence.

HTTP and HTTPS

HTTPS is the same protocol inside a TLS encrypted tunnel, on port 443 instead of 80. It gives three things:

Other services

  • File server: a shared place for documents, with permissions per user or group, and one backup covering everybody. On Windows networks the protocol is SMB; on Linux, NFS is common.
  • Print server: one queue for a shared printer, so jobs line up rather than clashing, and so one driver setting serves everyone.

Directory and authentication

A directory service (Active Directory, LDAP) holds the accounts, groups and machines for the whole organisation. It is what makes one username and password work on every computer in the building, and what lets an administrator disable a leaver in one place.

Time, logs and monitoring

The quiet services that make everything else possible:

  • NTP keeps every clock in step. Without it, logs from different machines cannot be lined up and certificates start failing.
  • Syslog collects log messages centrally, so that evidence survives the machine that produced it.
  • SNMP lets a monitoring system ask switches and routers how they are doing, and raise an alert before a human notices.

Virtualisation and the cloud

One physical server usually runs several virtual machines, each behaving like a separate computer. It costs less, is quicker to rebuild after a failure, and lets a test copy run beside the live one. When those virtual machines live in somebody else's data centre and you rent them by the hour, it is called the cloud. The networking ideas do not change: there are still addresses, subnets, gateways and firewall rules, and they are still the thing that goes wrong.

Which of these are in the workbench DHCP, DNS and HTTP, because they are the three you can see working end to end. The rest are exam knowledge, and they all sit on top of exactly the same layers.
Your turn: Why does an organisation care so much that NTP is working on every device?
Show the answer

Because logs, certificates and authentication all depend on clocks agreeing. If two servers disagree by ten minutes, you cannot work out what order events happened in during an investigation, Kerberos logins start failing, and TLS certificates can appear expired or not yet valid.

The order to build in

When a task has this many parts, the order matters. Work bottom up, the same way you would fault find:

  1. Layer 1. Every cable in, every link light green.
  2. Layer 3. The server's own fixed address. Then the DHCP scope, then renew the clients.

  4. Services. DNS records, then the web page.
  5. Test by name. nslookup, then web.
  6. The internet. Ping the cloud, then fetch a site out there.

What an access point actually is

An access point is a bridge. On one side it has a normal Ethernet port plugged into a switch. On the other it has a radio. A frame arriving by radio is put onto the wire, and a frame arriving on the wire for a wireless device is put on the air. The AP does not route and it does not hand out addresses: your DHCP server and your router do that, exactly as before.

The box most people have at home is four devices in one case: a modem, a router, a switch and an access point. In a school or an office those are four separate things, which is why the diagrams look different.

SSID, channels and bands

TermWhat it means
SSIDThe network name people see in the list. It is just a label, and hiding it is not security.
BSSIDThe MAC address of the radio. Several APs can share one SSID and have different BSSIDs.
ChannelThe slice of radio spectrum in use. Overlapping channels interfere.
Band2.4 GHz goes further and through walls but is crowded and slower. 5 GHz is much faster with less interference but a shorter range. 6 GHz (Wi-Fi 6E) is faster still and shorter again.

On 2.4 GHz there are only three channels that do not overlap: 1, 6 and 11. Neighbouring access points should alternate between those three. On 5 GHz there are many more, so this is much less of a problem.

Joining a network

  1. The AP sends a beacon several times a second, announcing its SSID.
  2. The client sends a probe, asking who is out there.
  3. Authentication and association: the client proves it knows the password and the AP accepts it.
  4. Then normal DHCP, exactly as on a cable.

In the workbench, a laptop or a phone associates with an AP whose SSID and password match its own settings. Get either wrong and the link is simply not there.

Roaming and coverage

One AP covers perhaps 30 m indoors. A building needs several, all sharing one SSID and one password, on different channels, with about 15 to 20 per cent overlap so that a laptop never falls into a gap. The client, not the AP, decides when to move. That is why a laptop sometimes clings to a weak AP across the building: it is waiting for the signal to get bad enough to bother.

Wireless security

A cable has to be plugged in to be attacked. Wireless is broadcast to the car park, so the encryption has to do the work.

The standards, worst to best

StandardVerdict
Open (no password)Everything readable by anyone in range. Only for a guest network that leads nowhere useful.
WEPBroken since 2001. Can be cracked in minutes. Never use it.
WPA with TKIPOld and weak. Replace it.
WPA2 with AESThe sensible minimum. Still fine when the password is strong.
WPA3Current. Much harder to attack offline, and encrypts even open networks.

Set WPA2 or WPA3 and nothing else. If a device is so old that it can only do WEP, put it on its own isolated VLAN and treat it as untrusted.

Personal and enterprise

  • WPA2-Personal (PSK) uses one password shared by everyone. Simple, and the standard choice at home. The problem is that a leaver takes the password with them, and changing it means changing it on every device.
  • WPA2-Enterprise (802.1X) makes each person sign in with their own username and password, checked against a RADIUS server. Disabling one account locks out one person. This is what schools and businesses use.

Guest networks

A guest network should be a separate VLAN that can reach the internet and nothing else. Add client isolation so that guests cannot see each other either, and a bandwidth limit so that one person streaming does not ruin the day for the rest.

The attacks worth knowing

  • Evil twin: an attacker runs an access point with the same SSID as yours, often with a stronger signal. Devices join it, and the attacker sees everything that is not separately encrypted.
  • Deauthentication: cheap kit can knock clients off a network, often as a first step towards making them join an evil twin.
  • WPS: the push-button pairing feature has a known flaw in the PIN method. Switch it off.
  • Weak passphrase: WPA2 passwords can be captured and attacked offline at enormous speed. A long passphrase of several unrelated words beats a short complicated one.

What good practice looks like

  • WPA2-AES or WPA3, with a long passphrase, or 802.1X where you can run it.
  • WPS off, and the admin password on the AP changed from the default.
  • Guests on their own VLAN with client isolation.
  • Firmware kept up to date.
  • Sensible transmit power: turning it to maximum mostly means a bigger car park.
What WPA2 does not protect you from Anybody who has the password is inside. On a shared-password network, one person running a capture can decrypt other people's traffic. HTTPS still matters even on a network you trust.
Common mistakes
  • Leaving the default admin password on the access point. The password to get online is not the password to configure the device. Change both.
  • Hiding the SSID and calling it security. The name is still in every frame your own devices send. It stops nobody and makes life harder for your users.
  • MAC filtering as the only control. MAC addresses travel in the clear and can be copied in seconds. It is a speed bump, not a lock.

The till goes on its own VLAN, ideally on a cable rather than wireless, with WPA2 or WPA3 and a strong passphrase, and firewall rules that stop anything on the guest VLAN from reaching it.

Threats and attacks

Most of what goes wrong is not clever. It is a password, a click, or a port nobody switched off.

The three things attackers want

Security is usually described as the CIA triad, and every attack breaks at least one part of it:

MeansBroken by
ConfidentialityOnly the right people can read itEavesdropping, theft, a leaked password
IntegrityNobody can change it without being noticedA man in the middle, a tampered file
AvailabilityIt is there when you need itDenial of service, ransomware, a dead switch

A good exam answer names which of the three an attack targets and why.

Attacks that use the network

  • Eavesdropping (sniffing): capturing traffic. Easy on a hub or a wireless network, harder on a switch, which is one reason switches replaced hubs.
  • Man in the middle: the attacker sits between you and the server. ARP poisoning is the classic way in on a LAN: send false ARP replies so that everyone thinks the attacker's MAC address belongs to the router.
  • Denial of service: flood a target until it cannot answer. DDoS does it from thousands of hijacked machines at once, which is why it is so hard to block.
  • Spoofing: forging a source address, whether MAC, IP, email or DNS, to pretend to be someone else.
  • Rogue devices: an access point or a switch plugged in by a user, bypassing every control you have.

Attacks that use people

Technical controls are the easy part. Social engineering goes round them:

  • Phishing by email, smishing by text, vishing by phone.
  • Pretexting: a convincing story. "I am from IT, we need to check your password."
  • Tailgating: following someone through a door that needs a badge.
  • Shoulder surfing and discarded paper, both still remarkably effective.

Training, and a culture where it is fine to say "I will ring you back on the published number", beats any firewall.

9.2 · Security and reliability

Firewalls and access rules

A firewall is a list of rules read from the top down. Understand the order and you understand firewalls.

What a firewall does

It inspects traffic and decides whether to allow it or drop it, based on rules. Each rule usually names:

  • the source address or network,
  • the destination address or network,
  • the protocol and port,
  • the action: permit or deny.

The two rules that matter most

  1. Rules are read in order, and the first match wins. A permit above a deny means the deny never happens.
  2. There is an invisible deny at the bottom. Anything not explicitly permitted is dropped. This catches people out constantly: add one rule to an empty list and you have just blocked everything else.

Read that from the top: staff may reach the web server on port 80; everything else from staff to the server network is blocked; everything else at all is allowed.

Types of firewall

TypeHow it decides
Packet filterLooks at addresses and ports only. Fast, simple, easily fooled.
StatefulRemembers connections, so replies to traffic you started are allowed automatically. The normal choice.
Application layer / proxyUnderstands HTTP, email and so on, so it can block by content, not just port. Slower.
Next generationStateful plus application awareness, user identity, and intrusion prevention in one box.

A stateful firewall is why you can browse the web without writing a rule for every website: the reply is part of a connection you began.

Where firewalls sit

  • At the edge, between your network and the internet. Always.
  • Between internal zones, so that a compromised guest VLAN cannot reach the servers.
  • On each machine, as a host firewall. Defence in depth: if one layer fails, another is still there.

A DMZ is a separate zone for anything the public must reach, such as a web or mail server. The internet can reach the DMZ, the DMZ can reach very little of the inside, and so a server that is broken into does not hand over the rest of the network.

Writing rules in the workbench

Open the router, choose Security, and add rules. Each has a source, a destination, a port and an action, and they are applied in the order they appear. The trace tells you exactly which rule stopped a packet, which is the single most useful thing a firewall log can do.

Permit what you need, deny the rest The professional habit is a default deny, then a short list of permits that you can explain. A list that grew by adding a permit every time something broke is a list nobody understands, and that is its own kind of risk.
Common mistakes
  • Putting a specific deny below a general permit. The permit matches first and the deny is never read. Specific rules go above general ones.
  • Forgetting the invisible deny at the end. Add one permit rule to an empty list and everything else stops. Test from a client, not from the router.
  • Blocking ICMP everywhere. It feels safer, and then nobody can use ping or tracert to diagnose anything. Block it at the edge if you must, not internally.
Your turn: A rule permits TCP port 80 from the staff VLAN to the server. Staff say the intranet is still unreachable, but they can ping the server. What have you forgotten?
Show the answer

Almost certainly DNS, on UDP port 53, which has no rule and so hits the implicit deny. The ping works because ICMP is handled by a different rule or is allowed elsewhere. Name resolution fails first, so the browser never even tries port 80.

Hardening a network

Hardening is a list of unglamorous jobs. Done properly, it removes most of the opportunities an attacker is looking for.

On every device

  • Change default passwords. Lists of factory defaults are a web search away.
  • Patch. Most successful attacks use a hole that was fixed months earlier.
  • Switch off what you are not using: services, protocols, and unused physical ports.
  • Separate admin accounts from everyday accounts, and use multi-factor authentication on both where you can.
  • Log centrally, so that evidence survives the machine that produced it.

On the network

Follow least privilege: everyone gets exactly the access their job needs, and no more. A leaver's account that still works three months later is one of the most common audit findings there is.

Physical security

None of the above matters if somebody can walk up to the switch:

  • Comms cabinets locked, in rooms with controlled access.
  • Servers in a locked room, not under a desk.
  • Screens locked when unattended, and cable locks on equipment in public areas.
  • A clear policy on removable media, and full-disk encryption on anything that leaves the building.

Policies and the law

A written acceptable use policy tells people what is allowed and gives the organisation grounds to act. In the UK, the Data Protection Act 2018 and the UK GDPR require personal data to be kept securely, and the Computer Misuse Act 1990 makes unauthorised access an offence, including on your own employer's systems. Testing someone's security without written permission is a crime, however good your intentions.

Permission in writing, always Scanning, capturing traffic or trying passwords on a network you do not own is illegal in the UK even if nothing is damaged. Practise in a simulator like this one, or on equipment that is yours.

9.4 · Security and reliability

Backups and redundancy

Everything fails eventually. The question is whether that is a shrug or a disaster, and that is decided before it happens.

Backups

A backup is only real when it has been restored. Three questions decide the design:

  • RPO (recovery point objective): how much work can we afford to lose? That sets how often you back up.
  • RTO (recovery time objective): how long can we be down? That sets how you restore.
  • Retention: how far back do we need to go? Ransomware that sat quietly for six weeks makes this matter.
TypeBacks upRestore
FullEverythingOne step, slowest to take
IncrementalWhat changed since the last backup of any kindSmallest and quickest to take, needs the full plus every increment to restore
DifferentialWhat changed since the last full backupGrows each day, needs only the full plus the latest one

The 3-2-1 rule is the standard to quote: three copies of the data, on two different kinds of media, with one of them off site. Modern advice adds that one copy should be offline or immutable, because ransomware deliberately looks for the backups.

Redundancy

Removing single points of failure, each at its own cost:

  • Dual links between switches, with spanning tree keeping them loop free.
  • Two routers sharing one virtual gateway address, so that a failure is invisible to clients.
  • RAID so that a failed disk does not mean a failed server. RAID 1 mirrors, RAID 5 spreads data and parity across three or more disks, RAID 10 does both.
  • Dual power supplies, and a UPS so that a brief cut does not take everything down, with a generator if the building must keep running.
  • Clustered or load-balanced servers, so that one machine can be lost or patched without an outage.
RAID is not a backup It protects against a disk dying. It does nothing about a deleted file, a corrupted database, a fire, or ransomware, all of which are faithfully written to every disk in the array at once.

Planning

A disaster recovery plan is written down, kept somewhere that does not depend on the systems it describes, and rehearsed. It names who decides, who to call, where the backups are and in what order things come back. The rehearsal is the part people skip, and it is the part that finds the backup nobody could actually restore.

Monitoring

You cannot protect what you cannot see. Monitoring watches links, devices, disk space and services and raises an alarm before users do. Good monitoring means the first person to know about a failed disk is the person who can replace it.

The questions to ask first

  • What changed? Almost nothing breaks by itself. Somebody patched, moved, upgraded or "tidied".
  • Who is affected? One user, one room, or everyone? That tells you how far up the tree the fault is.

Document what you found and what you did, and tell the user it is fixed and why. The next person to see this fault may be you, in eight months, with no memory of it at all.

One change at a time Changing three things and then testing means you have no idea which one worked, and you may have added a new fault while fixing the old one. Change, test, keep or undo, then move on.

The tools

Six commands and three pieces of kit cover almost everything. Here is what each one proves.

The commands

**ipconfig**, or ifconfig and ip addr on Linux. Shows what the machine thinks its settings are. ipconfig /all adds the MAC address, the DHCP server and the DNS servers. ipconfig /release and /renew force a new lease, and /flushdns clears the name cache.

**ping** sends ICMP echo requests. A reply proves the whole path works in both directions, at layers 1, 2 and 3. No reply proves less than people think: the packet may have arrived and the reply been lost, or ICMP may simply be blocked.

**tracert** (traceroute on Linux and macOS) lists every router on the way, by sending packets with a TTL of 1, then 2, then 3, so each router in turn reports the packet as expired. Where the list stops is where the problem begins.

**nslookup** asks a DNS server directly, which separates name problems from network problems.

**arp -a** shows which MAC address this machine thinks belongs to each IP address on its own network. Useful when two devices have the same address, or when something is poisoning the cache.

**netstat -an** lists the connections and listening ports on a machine. The way to answer "is the service actually running and listening?"

The kit

ToolWhat it tells you
Link lightsFree, instant, and the first thing to look at. Off means layer 1.

Tone generator and probeWhich of the 300 unlabelled cables in the cabinet is the one you want

Reading a tracert

The first two hops answer, so your LAN and your router are fine. The path stops after 10.0.0.1, so look at that device and the link beyond it. Note that a single timed-out hop in the middle, with later hops answering, usually just means that one router is set not to reply, which is normal and not a fault.

Fault find: one

How to approach it

  1. Look at the link lights first. One of them is not green. That is layer 1, and it is the cheapest fault to find.
  2. Then look at the addresses. Open each PC and compare them carefully. They are all in the same range, so something subtler is wrong.
  3. Only then start pinging. Test from each PC to the server and note which ones fail.

The second fault is the interesting one. Two devices can have addresses that look as though they belong together and still be on different networks, because the mask decides what counts as local. A PC with the wrong mask can still reach some things, which makes the fault look intermittent and random when it is nothing of the sort.

Change one thing, then test Fix the cable, mark your work, and see which criteria go green. Then fix the address. Working this way tells you which fix did what.

Three faults across two networks and a router. Work bottom up and it falls apart in a few minutes.

The order to check

  1. Layer 1. Every link light. Remember that a router interface can have a perfect cable and still be down, because it starts switched off.
  2. Layer 3, on the router. Open it and look at its interfaces: addresses, masks and whether each one is on.
  3. Layer 3, on the hosts. ipconfig on each PC. Address, mask and gateway. An empty gateway means a machine that can only talk to its own network, which exactly matches the symptom.
  4. Test after each fix.

The symptom is a clue

"Sales can reach each other but nothing else" tells you a great deal before you touch anything. Local traffic works, so the cable, switch and addressing on that network are fine. Everything that needs to leave fails, so the fault is on the way out: the gateway setting, the router interface, or the route.

Learning to read a symptom like that, and to say what it rules out, is most of what makes an experienced engineer quick.

Check the gateway address, not just that there is one A gateway of 10.1.2.254 looks perfectly reasonable until you notice the router is on 10.1.2.1. The PC sends every outbound packet to an address that nothing answers to, so ARP fails and the packet is dropped before it goes anywhere.
Your turn: A PC has a correct address and mask, and its gateway is set to an address on its own network that no device uses. What exactly happens when it pings a machine on another network?
Show the answer

The PC works out the destination is not local, so it ARPs for the gateway. Nothing answers, so it never gets a MAC address to send the frame to, and the ping fails with "destination host unreachable" from the PC itself rather than a timeout. No packet ever leaves the machine.

10.5 · Troubleshooting

Fault find: three

The hardest one. Two sites, VLANs at one end, three faults, and no new equipment allowed.

What to look at

This network uses everything from Parts 5 and 6 at once, so work through them in order:

  1. The switch to router link. With VLANs in play, that link has to be a trunk. If it has been set to an access port, only one VLAN reaches the router, and the symptom is that half the network works perfectly while the other half does nothing.
  2. The router sub-interfaces. One per VLAN, each with the address the PCs are using as their gateway.
  3. The static routes. They come in pairs. A packet getting there and nothing coming back is almost always a missing route on the far router. tracert shows you exactly how far it gets.

A thought about this kind of fault

Each of these three faults produces a different, very specific symptom, and none of them is a broken cable. That is normal on a network that has been running for a while: the physical layer is usually fine, and the faults live in configuration that somebody changed for a good reason at the time.

This is why the notes matter. A trunk that somebody turned into an access port last Tuesday to make a laptop work is invisible unless it is written down or you go and look.

Use tracert here From HQ-PC, trace to the branch PC. If the trace reaches the branch router and stops, the outward path is fine and the return route is missing. That single test saves you from checking everything else.
Your turn: Traffic reaches the far site but no reply comes back. The far router can ping its own local PC perfectly. What is wrong, and why does a ping from the far side fail too?
Show the answer

The far router has no route back to the originating network, so it does not know where to send the reply and drops it. A ping started from the far side fails for the same reason: it gets there, and the reply has nowhere to go. Static routes always have to be configured at both ends, or you need a default route pointing at the other router.

Build it from the brief

No starting network, no step-by-step instructions. A written brief, an empty canvas, and twenty marks.

How to work through a brief

Read it twice, then turn it into a list before you touch anything. A brief hides its structure in prose, and your first job is to pull it out:

From the briefWhat it means you must build
Two departments on two networksTwo VLANs, two subnets, and something at layer 3 to join them
Gateway is always .1The router gets 192.168.10.1 and 192.168.20.1
A server running a website, reachable by nameHTTP on, DNS on, a record pointing the name at the server, and every client told where the DNS server is
The router reaches the internetA /30 to the cloud, and a default route

Build in this order

  1. Devices. Drag them out and name them. Place them so the diagram reads left to right.
  2. Cables. Use Auto if you want to be quick, then check each type afterwards.
  3. VLANs. Create 10 and 20 on the switch, then put the access ports in them.
  4. The trunk. One port on the switch, up to the router.
  5. The router. A sub-interface per VLAN, with the gateway addresses, and the interface switched on.
  6. Addresses. Each PC on its own network, with the right gateway and the DNS server set.
  7. Services. The server's own address first, then HTTP, then the DNS record.
  8. The internet. The /30 link and the default route.

Press Mark my work after every stage. There is no penalty, and it turns one large problem into eight small ones that each either go green or tell you why not.

Reading the marking

Each criterion that fails says what it found, not just that it failed. "The router has 192.168.10.1. It needs 192.168.10.1 and 192.168.20.1" is a sentence telling you exactly what to do next. Work the list from the top: the early criteria are the foundations, and the later ones cannot pass until they do.

Stuck on the last two marks They are the end-to-end tests, and they almost always fail for the same three reasons: no DNS server set on the client, no default route on the router, or a sub-interface with the wrong VLAN number. Check those before anything else.
Your turn: The brief says the gateway is always the first address. Why do networks adopt a convention like that at all?
Show the answer

Because it removes a decision and a lookup. Anyone who knows the subnet knows the gateway, documentation stays short, scripts can work it out, and a new engineer can guess correctly on their first day. Some organisations use the last address instead. Either is fine; what matters is that it is the same everywhere.

Subnetting test

Ten questions on addressing, which is the part that carries the most marks in every exam on this subject.

Before you start

Work on paper. The block size method is all you need:

  1. Block size = 256 − the interesting octet of the mask. For /26 the mask is 255.255.255.192, so 256 − 192 = 64.
  2. Count up in that block size from zero: 0, 64, 128, 192.
  3. Your address sits in one of those blocks. The one it falls into is the network address.
  4. The broadcast address is one below the next block, and the usable range is everything in between.

If you got one wrong

Press Check my answers and read the explanation under each one. Then go back to section 4.4 and section 4.5, redo those exercises, and come back. Subnetting is a skill rather than a fact: nobody understands it by reading, and nearly everybody gets it by doing twenty of them.

The calculator There is a subnet calculator in section 4.4. Use it to check your working after you have done it by hand. Used the other way round it teaches you nothing, and the exam will not have one.

Glossary

Addressing

TermMeans
MAC addressA 48-bit address burned into a network card, written like 00:1A:2B:3C:4D:5E. Used inside one network only.
IP addressA logical address identifying a device on a network, such as 192.168.1.42. Can be changed.
Subnet maskSays which part of an address is the network and which is the host, such as 255.255.255.0.
PrefixThe same thing written as a count of network bits, such as /24.
Network addressThe first address in a subnet. Names the network itself, never a device.
Broadcast addressThe last address in a subnet. Reaches every device on it.
Default gatewayThe router address a device sends anything non-local to.
APIPAA 169.254.x.x address a device gives itself when DHCP does not answer.
Public and privatePrivate ranges (10.x, 172.16 to 172.31, 192.168.x) are reusable inside organisations and not routed on the internet.
NATNetwork address translation: many private addresses sharing one public one.
IPv6The 128-bit replacement for IPv4, written in hexadecimal, such as 2001:db8::1.

Devices

TermMeans
HubA repeater. Copies every signal to every port. Obsolete.
SwitchForwards frames by MAC address, learning which device is on which port. Layer 2.
RouterForwards packets between networks by IP address. Layer 3.
FirewallAllows or blocks traffic by rule.
Access pointBridges a wireless network onto a wired one.
ServerA machine that provides a service to clients.
NICNetwork interface card: the hardware with the MAC address.

Protocols

TermMeans
EthernetThe standard for wired LANs, layers 1 and 2.
ARPFinds the MAC address that belongs to an IP address.
IPAddresses and routes packets between networks.
ICMPError and test messages. ping and tracert use it.
TCPReliable, ordered, connection-based delivery. Has a handshake.
UDPFast, connectionless delivery with no guarantees.
DHCPHands out addresses and settings automatically.
DNSTurns names into addresses.
HTTP / HTTPSFetches web pages, in the clear or inside TLS encryption.

Concepts

TermMeans
LAN / WANOne site, or a network joining sites over distance.
